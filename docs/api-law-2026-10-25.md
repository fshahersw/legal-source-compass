# Law and government APIs (wave 1025, worker api-law)

Official law and government APIs added as published datasets, app pages and self-updating sources. Everything here comes
from the publisher's own API or feed; every record carries its official URL, the API request it came from (without the
key) and the time it was read. Unknown values read "Not recorded". Nothing is published by this worker; the lead runs the
RUNBOOK below.

Insights family `government2` (database/contracts/insights-government2-v1.sql): Regulations.gov proposed rules, final
rules and notices posted per agency and year; public comments on the year's proposed rules (a sum only when every
proposed rule has a count, else Not recorded with "Comment counts read for X of Y"); amendments submitted, nominations
received and confirmed, committee reports issued, hearings published, bill text versions and enrolled bills per year;
distinct MDLs mentioned in each company's 10-K (a mention, never membership).

### Accuracy rules applied

- Links between records are exact: a Regulations.gov document links to the Federal Register record whose source URL is
  `https://www.federalregister.gov/d/<frDocNum>` (415 of 415 in the sample), and to CFR parts only through that record.
  An amendment links to the amended bill, a report to its bills and its GovInfo package, a hearing to its committee, only
  when the held id is exactly equal. A judicial nomination links to the held `judicial_nominations` record of the same
  Congress and PN citation only.
- Comment counts are Regulations.gov's `totalElements` for the document or docket, each with the date read; missing counts
  are Not recorded, never 0.
- 10-K text is the filing's visible text with tags removed (rendering rule stored per record), never rephrased; every span
  carries its offsets, the sha256 of the slice, the raw document's sha256 and the accession number. MDL numbers and held
  MDL captions are recorded as mentions only.
- GAO decision summaries are as published (GAO shortens them with "…"); GAO's feed escapes descriptions twice, which the
  parser decodes (`unescapeTwice`).

### Blocked or limited (recorded, not worked around)

- **USPTO PTAB**: the Open Data Portal PTAB API answers 401 "Missing Authentication Token" without an ODP API key; no key
  is available. Not built.
- **GAO decision history**: gao.gov's robots.txt asks every crawler for 420 s between requests, so the decision archive
  is not copied; `gao_legal_decisions` grows from its first run (the feed holds ~25 items), and GovInfo GAOREPORTS covers
  1994-2008.
- **Regulations.gov comment counts**: one request per document or docket at 1,000 requests an hour (key shared with other
  jobs). Full counts for every document are a multi-day job; the acquisition reads proposed rules first, then rulemaking
  dockets, then other documents with a comment period, newest first. The daily source adds 40 document counts and 30
  docket counts per run. Values not yet read stay Not recorded and the overview says how many were counted.
- **congress.gov web pages** answer 403 to automated clients; records link to them by Congress.gov's documented URL
  patterns, while every value comes from the API.

## RUNBOOK (lead)

All commands from the repository root. Keys are loaded inside the single command that needs them; never echo them.

```sh
KEY='set -a && eval "$(grep "^DATA_GOV_API_KEY=" private/scratch/secrets.env)" && set +a'
```

eval "$KEY" && node scripts/api_law/validate_samples.mjs --per 4                                  # exact API re-reads
python3 -I -B scripts/api_law/edgar/legal_proceedings.py verify --sample 4                        # 10-K re-fetch + spans

### 3. Publish (lead), then contracts

```sh
. private/scratch/env.sh && python3 -I -B scripts/api_law/publish_stream.py --publish <header.json>   # one dataset at a time
```

Then apply `database/contracts/api-law-v1.sql` (sources + `api_law_regs_overview_v1`) and
`database/contracts/insights-government2-v1.sql`, and run `select insights.refresh_government2('initial');`.

### 4. Self-updating sources

1. Function secret `DATA_GOV_API_KEY` (owner, dashboard) for `ingest-regulations-gov`, `ingest-congress-gov`,
   `ingest-govinfo`.
2. Deploy: `supabase functions deploy <name> --project-ref xosqzzsnhxcyehcnirpa --no-verify-jwt` for
   `ingest-regulations-gov`, `ingest-sec-enforcement`, `ingest-doj-press-releases`, `ingest-congress-gov`,
   `ingest-govinfo`, `ingest-gao-legal`.
3. First run of each source from SQL (ingest-v1.sql step 5) with `'source', '<id>'` for: `regulations_gov_documents`,
   `regulations_gov_dockets`, `sec_enforcement`, `doj_press_releases_2026`, `congress_amendments`,
   `congress_nominations`, `congress_treaties`, `congress_committee_reports`, `govinfo_bill_versions`,
   `govinfo_hearings`, `govinfo_committee_prints`, `govinfo_gao_reports`, `gao_legal_decisions`.
   (`doj_press_releases_2027` only after that partition is published.)
4. Check `select source, status, fetched, inserted, updated, unchanged, held, error from ingest.runs order by started_at desc;`
5. `update ingest.sources set enabled = true where id in (...);` and apply api-law-v1.sql again (section 3 schedules:
   off-hour minutes, one job per source).

Dry run of any source without writing (reads the live corpus only): `. private/scratch/env.sh && eval "$KEY" &&
node scripts/api_law/dry_run.mjs --source congress_nominations --show 3`.

### 5. Verification SQL (after publishing)

```sql
select id, ready, imported_records from public.corpus_datasets where id in ('regulations_gov_documents',
  'regulations_gov_dockets', 'congress_amendments', 'congress_nominations', 'congress_treaties',
  'congress_committee_reports', 'govinfo_hearings', 'govinfo_committee_prints', 'govinfo_bill_versions',
  'govinfo_gao_reports', 'gao_legal_decisions', 'company_sec_legal_proceedings');
select (public.api_law_regs_overview_v1() -> 'agencies') -> 0;
select metric_id, count(*), count(value), min(period), max(period) from insights.facts
  where metric_id in (select id from insights.metrics where family = 'government2') group by 1 order by 1;
-- every FR-linked document points at a held Federal Register record
select count(*) from public.corpus_records d where d.dataset = 'regulations_gov_documents'
  and d.filters -> 'fr_linked' ->> 0 = 'in_corpus' and not exists (select 1 from public.corpus_records f
  where f.dataset = 'federal_register_history' and f.source_url = 'https://www.federalregister.gov/d/' || (d.filters -> 'fr_doc' ->> 0));
```

## Staged samples (private/build/w1025_api-law, not published)

(446 documents, 3,099 dockets, 150 comment counts), Congress.gov 118th-119th Congress lists (11,716 amendments, 300 with

GovInfo equal the stored fields (`validation.json`); 4 of 4 re-fetched 10-K documents reproduce the raw and rendering
hashes and every stored span (`edgar/verify.json`).
