# Case law below the Supreme Court — v2 (wave 1025, 2026-10-25)

Worker CASELAW. Scope: published case law of every court level below the Supreme Court — federal courts of
appeals, state courts of last resort, state intermediate appellate courts, federal district courts and other
courts — searchable, citable and linked, with exact provenance. Source: CourtListener bulk data, snapshot
2026-09-30 (public bulk-data bucket), with GovInfo USCOURTS as official provenance for district opinions.
Nothing here writes production; the lead runs the loads.

## 3. Design

### Storage (text)
Reading records exactly as stage 2 (`caselaw-read/1`, one gzip member per opinion, the app's parser unchanged),
written straight from one streaming pass over the 55 GB opinions file (no stage-1 raw shards for the new tiers:
no duplicate Storage). Each record adds `source` = {file, etag, segment, offset of the CSV record, record_sha256,
field, raw_sha256, raw_bytes, CourtListener sha1, date_created/modified, page_count} and `builder`. Objects close at
a cluster change once they reach 24 MB, one open object per tier per unit, content-addressed keys
`caselaw/read/2026-09-30/t<tier>/v2/u<unit>/…-<sha12>.jsonl.gz` (pass the existing key checks of the app and of
`caselaw.objects`). The file is in heap order, so 74% of multi-opinion clusters span units: the case page now reads
one range per object (`readRanges`), usually one.

### Database
`database/contracts/caselaw-v2.sql` (on top of caselaw-read-v1; idempotent; all functions SECURITY DEFINER,
`search_path = ''`, service_role only):
* tiers widened to 1..7 (validated constraint); courts gain `level`, `system`, `jurisdiction`, `parent_court_id`,
  `url`, dates, `in_use`, `cases_with_text`; cases gain `cap_file` (Caselaw Access Project crosswalk), `source`,
  `attached_build`;
* `caselaw_search_v1` / `caselaw_courts_v1` re-created with `tier <= 3` (the deployed app keeps its view);
* read: `caselaw_case_v2`, `caselaw_courts_v2`, `caselaw_search_v2` (tiers, court, state, system, dates, status;
  citation mode with reporter aliases), `caselaw_court_years_v2`, `caselaw_court_cases_v2`, `caselaw_fulltext_v2`
  (tier 1 from `opinion_fts`, tiers 2-7 from `caselaw.text_v2`), `caselaw_text_coverage_v2`, `caselaw_status_v2`;
* **`caselaw_resolve_v2(p_citation text, p_year int default null, p_court text default null)`** →
  `{status: resolved|ambiguous|unresolved, reason: not_held|not_a_citation|filtered_out, cluster_id, candidates[≤20],
  parsed{volume, reporter, page, pin, year, court, cite_key, shape, parallel_ignored}, matched_via}`; resolved only
  when exactly one held case carries the citation (after optional explicit year/court filters); ambiguous lists
  candidates and never chooses; parallel citations resolve the first; pin cites and parentheticals are parsed;
  neutral cites (`2021-Ohio-1234`) work; `caselaw_resolve_many_v2(text[])` takes up to 500 (worker CITE);
* load: `caselaw_load_courts_v2`, `caselaw_load_cases_v2` (tiers 4-7 only, never touches opinions, requires
  computed `cited_by`), `caselaw_attach_opinions_v2` (merge pointers by opinion id), `caselaw_load_text_v2`
  (scope `full` | `prefix`, text verified by sha256, case facts taken from `caselaw.cases`),
  `caselaw_refresh_court_counts_v2`.

### Text search: owner decision (see §5)
`caselaw.text_v2` is list-partitioned by tier with a GIN index; the loader indexes either every word (8,000-word
parts, star-page markers blanked, as v1 format 2) or the first N words of each opinion.

### App
`/cases` filters by court level (7), state and court; full text across indexed tiers with a coverage line;
`/cases/courts` (directory by level and state, text coverage) and `/cases/courts/<court>` (decisions by year chart,
year/sort filters, list); case pages show court level, state, the CAP crosswalk and each opinion's source bytes;
citation links are re-checked live so links into newly loaded courts open here. v1 RPCs are used automatically
until the v2 contract is applied.

### Official federal opinions (GovInfo USCOURTS)
Exact crosswalk, no names: a CourtListener district docket number of the form `1:15-cv-08672` gives package
`USCOURTS-<court>-1_15-cv-08672`; the package must carry the same court and case number, and a cluster links to a
granule only when exactly one granule was issued on the cluster's filing date. Sample (40 cases each, since 2004):
E.D.N.Y. 37 packages, 35 linked; W.D. Tex. 36 packages, 34 linked; S.D.N.Y. 0 (it does not publish to GovInfo).
Responses kept unchanged with sha256 under `private/acq/w1025_caselaw/govinfo/`. Proposed use: a provenance link
("official opinion PDF at GovInfo") on matched district cases, and the collections endpoint as a daily delta source
for new district opinions (not built in this wave).

### Caselaw Access Project
`static.case.law` robots.txt disallows all user agents (checked 2026-10-23), so it is not used. CourtListener already
merged the Harvard corpus and publishes the exact file per cluster (`filepath_json_harvard`; 1,338 of 1,752 sample
cases carry it); v2 stores it as `cap_file` and shows the CAP case id, reporter, volume and page.

## 5. Owner decisions needed

   first 1,000 words of every opinion of tiers 2-7 (**+41 GB**, recommended first step); every word of tiers 2-3 and

   store plus raw markup; deleting them would offset the growth, but they are the only stored copy of the raw markup
   once CourtListener rotates the 2026-09-30 snapshot. Keep or delete?
3. **Which tiers**: recommended 4 and 5 first (4.6 M cases); tiers 6 (includes agency tribunals: BIA, BVA, MSPB,
   PTAB, TTAB, ASBCA) and 7 (2,618 state trial courts, few opinions each) after review.
4. **Exclusions**: executive legal opinions (`ag`, `olc`, state DOJ) and state attorney general opinions are not
   loaded as case law; confirm.
5. **GovInfo**: approve showing the official GovInfo opinion link on exactly matched district cases.

## 6. RUNBOOK (lead)
All commands from the repository root; credentials only inside the command that needs them.

```
# 0. contract (SQL tool): database/contracts/caselaw-v2.sql (after caselaw-read-v1.sql). Then:
#    select public.caselaw_status_v2();   -- tiers 1-3 as before
# 1. court registry (seconds; 100 KB)
python3 -I -B scripts/caselaw_v2/courts.py
# 2. clusters of tiers 4-7 (~10 min, 2.47 GB streamed; meta.duckdb ~1.1 GB)
python3 -I -B scripts/caselaw_v2/clusters.py --run all --groups all
# 3. citations, panels, people (~1 min)
python3 -I -B scripts/caselaw_v2/citations.py --run all
# 4. opinions pass with verified uploads (~3.5-4 h, 55.25 GB streamed, ~27-30 GB uploaded; local peak ~0.5 GB:
#    each object is deleted after its readback; attach rows ~70 MB, omap ~90 MB). Resumable: rerun the same command.
. private/scratch/env.sh && nohup python3 -I -B scripts/caselaw_v2/opinions.py run --run all --units all \
   --procs 3 --workers 4 --upload >> private/build/w1025_caselaw/logs/opinions_all.log 2>&1 &
python3 -I -B scripts/caselaw_v2/opinions.py status --run all
# 5. cited_by from the citation map (~2 min; needs all 20 units)
python3 -I -B scripts/caselaw_v2/citedby.py --run all
# 6. checks, then rows per tier (cases ~90 B gz each: tier 4 ~300 MB, build/load/delete one tier at a time)
python3 -I -B scripts/caselaw_v2/verify.py --run all --from-storage 40   # reads 40 uploaded objects back
python3 -I -B scripts/caselaw_v2/rows.py --run all --tiers 4,5      # then 6,7 after the owner's decision
python3 -I -B scripts/caselaw_v2/load.py plan --run all
. private/scratch/env.sh && python3 -I -B scripts/caselaw_v2/load.py load --run all --build v2-1
# 7. text index (owner's scope; e.g. first 1,000 words of tiers 4 and 5; reads objects back from storage)
. private/scratch/env.sh && python3 -I -B scripts/caselaw_v2/load.py text --run all --build v2-1 --scope prefix \
   --prefix-words 1000 --tiers 4,5
# tiers 2-3 text is in the stage-2 store: index it with the same RPC through a small reader of
# private/build/caselaw_read/read/index (load_caselaw.py fts_batches + caselaw_load_text_v2) when the owner decides.
# 8. insights: select insights.refresh_caselaw('caselaw v2');  (court/year facts for the new courts)
```
