Main's `review_publisher_code_v2.py` has subsequent section-body/reverse-completeness checks and review guards absent from the PR snapshot; replacing it with the older branch version would remove those safeguards. A normal three-way merge is not equivalent to that replacement, so integration still requires hunk-by-hunk resolution on current main.

For #132/#181–183, arbitrary substring presence in either a URL or printed href is weaker than an exact bounded publisher path association. Consolidating the implementation should test neighboring numbers, unrelated paths, query strings, and other matters on the same hub. A captured hub alone does not establish association for every linked document.

For #134/#136/#145/#150, current `build-queue.mjs` treats any supplied `case_number` as `exact_sourced_master_docket_literal`; its fallback `printed_mdl_literal` explicitly represents a different evidence type. These PRs must use the appropriate field even when the MDL number itself is accurately transcribed.

The #111 caption conflict is documented in [`courtlistener-backfill-contract.md`](courtlistener-backfill-contract.md) (paragraph beginning “The finalized 2026-10-02 live batch”) and [`corpus-enrichment-release-2026-10-02.md`](corpus-enrichment-release-2026-10-02.md): both identify the 2846 scope as Davol/Bard polypropylene hernia mesh, distinct from Physiomesh 2782. No new inference from caption or product should replace the retained native evidence.

## Method and limits

GitHub open-PR metadata was read with `gh pr list`; each `refs/pull/<number>/head` was fetched into `refs/remotes/origin/pr/<number>`. Every head was tested with `git merge-base --is-ancestor <head> origin/main`. The review compared the merge-base-to-head diff, affected-file blobs on current main, and parsed literal `MATTERS` objects without executing PR code. Stack ancestry was checked independently. Commit patch-equivalence alone was not used as proof of functional duplication.

This triage does not certify current external court pages, stored PDF completeness, successful prior private capture runs, or merge readiness. It identifies what is still distinct in Git and which changes require evidence or regression tests. It makes no database, Storage, publication, or GitHub mutation.
